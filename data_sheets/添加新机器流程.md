# 添加新多方块机器的流程

以「进阶化学反应釜」为样板，记录从头加一台多方块机器的完整清单。

**核心设计**：方块类 `GTChemicalReactorMachineBlock` 和实体类 `GTChemicalReactorMachineBlockEntity` 是共享的，新机器只注册、不复制。所有差异通过覆写钩子表达。

---

## 一、必须理解的两条铁律

### 1. 结构文件要放两份

| 位置 | 谁读 | 用途 |
|---|---|---|
| `data/goldentweaks/multiblock/structures/<id>.json` | 服务端 | 结构校验、一键建造 |
| `assets/goldentweaks/multiblock/structures/<id>.json` | 客户端 | 投影仪预览 |

**两份内容必须完全一致。** 客户端用的是 `SimpleJsonResourceReloadListener`，它只读 `assets/`。只放 `data/` 的话，服务端能成型、投影仪却什么都画不出来——这个 bug 已经踩过一次。

### 2. 方块 id 决定一切，不要在代码里硬编码机器 id

过去散落着 `GTChemicalReactorMultiblock.MACHINE.get()`、`HOST_STRUCTURES` 映射表这类硬编码，导致进阶机器：界面秒关、投影仪失效、拆除还错方块。现在全部收敛到两个地方：

- **方块**携带自己的结构 id 与实体工厂（构造参数 `structurePath` + `tileFactory`）
- **实体**通过 `getMachineId()` / `menuType()` 等虚方法作答

新机器只需注册时传参，不再需要改任何共享代码。

## 二、Java 侧（4 个文件）

### 2.1 注册类

新建 `compat/avaritia_more_items/GTXxxMultiblock.java`，照抄 `GTAdvancedChemicalReactorMultiblock`：

```java
public final class GTAdvancedChemicalReactorMultiblock {

    /** 方块注册 id */
    public static final String ID = "advanced_chemical_plant_controller";

    public static final DeferredRegister.Blocks BLOCKS = DeferredRegister.createBlocks(GoldenTweaks.MODID);
    public static final DeferredRegister.Items ITEMS = DeferredRegister.createItems(GoldenTweaks.MODID);
    public static final DeferredRegister<BlockEntityType<?>> BLOCK_ENTITIES =
            DeferredRegister.create(Registries.BLOCK_ENTITY_TYPE, GoldenTweaks.MODID);
    public static final DeferredRegister<MenuType<?>> MENU_TYPES =
            DeferredRegister.create(Registries.MENU, GoldenTweaks.MODID);

    /** 菜单类型：客户端靠它选界面类 */
    public static final DeferredHolder<MenuType<?>, MenuType<GTChemicalReactorMenu>> MENU =
            MENU_TYPES.register("advanced_chemical_reactor", () -> IMenuTypeExtension.create(
                    (containerId, inventory, data) ->
                            GTChemicalReactorMenu.create(menuType(), containerId, inventory,
                                    data.readBlockPos())));

    private static MenuType<?> menuType() {   // 必须用方法，否则自引用编译不过
        return MENU.get();
    }

    /** 方块：复用同一个类。第二个参数是结构文件名，第三个是本机的实体工厂 */
    public static final DeferredBlock<GTChemicalReactorMachineBlock> MACHINE =
            BLOCKS.register(ID,
                    () -> new GTChemicalReactorMachineBlock(GTMultiblockBlocks.properties(),
                            "advanced_chemical_reactor", GTAdvancedChemicalReactorBlockEntity::new));

    /** 物品：第三个参数是 tooltip 里显示的机壳语言键 */
    public static final DeferredItem<BlockItem> MACHINE_ITEM =
            ITEMS.register(ID,
                    () -> new GTChemicalReactorItem(MACHINE.get(), new Item.Properties(),
                            "block.goldentweaks.shell_pp"));

    /** 方块实体类型：必须与方块一一对应，否则放置时崩溃 */
    public static final DeferredHolder<BlockEntityType<?>,
            BlockEntityType<GTAdvancedChemicalReactorBlockEntity>> MACHINE_ENTITY =
            BLOCK_ENTITIES.register(ID,
                    () -> BlockEntityType.Builder.of(
                            GTAdvancedChemicalReactorBlockEntity::new, MACHINE.get()).build(null));

    public static void register(IEventBus eventBus) {
        BLOCKS.register(eventBus);
        ITEMS.register(eventBus);
        BLOCK_ENTITIES.register(eventBus);
        MENU_TYPES.register(eventBus);
        GTXxxRecipes.register(eventBus);   // 若有独立配方类型
    }
}
```

**易错点**：

- `MACHINE_ENTITY` 的 id 必须与 `MACHINE` 的 id 一致。不一致会在放置时抛 `Invalid block entity`
- 忘了注册 `MENU_TYPES` → 界面打不开
- 忘了 `MENU` → 界面一打开就关闭（客户端找不到对应界面）

### 2.2 实体类

新建 `compat/avaritia_more_items/GTXxxBlockEntity.java`，继承 `GTChemicalReactorMachineBlockEntity`：

```java
public class GTAdvancedChemicalReactorBlockEntity extends GTChemicalReactorMachineBlockEntity {

    /** 结构文件名 */
    public static final String MACHINE_ID = "advanced_chemical_reactor";

    public GTAdvancedChemicalReactorBlockEntity(BlockPos pos, BlockState state) {
        this(GTAdvancedChemicalReactorMultiblock.MACHINE_ENTITY.get(), pos, state);
    }

    public GTAdvancedChemicalReactorBlockEntity(BlockEntityType<?> type, BlockPos pos, BlockState state) {
        super(type, pos, state);
    }

    @Override public String getMachineId()  { return MACHINE_ID; }
    @Override protected Block casingBlock() { return GTMultiblockBlocks.SHELL_PP.get(); }
    @Override protected String nameKey()    { return "block.goldentweaks.advanced_chemical_plant_controller"; }
    @Override protected RecipeType<GTChemicalReactionRecipe> recipeType() {
        return GTXxxRecipes.TYPE.get();
    }
    @Override protected MenuType<?> menuType() {
        return GTAdvancedChemicalReactorMultiblock.MENU.get();
    }
}
```

**六个钩子必须全部覆写**，漏一个就会出现诡异现象：

| 钩子 | 漏掉的后果 |
|---|---|
| `getMachineId()` | 读基础版的结构文件 |
| `casingBlock()` | 机壳数量校验用错材料 |
| `nameKey()` | 界面标题显示基础版名字 |
| `recipeType()` | 机器查不到自己的配方 |
| `menuType()` | **界面一打开就关闭** |

> `getPatternId()` 不用覆写，它已经由 `getMachineId()` 拼出来。

### 2.3 配方类型（若机器有独立配方集）

新建 `GTXxxRecipes.java`：

```java
public static final String DIRECTORY = "advanced_chemical_reaction";

public static final DeferredHolder<RecipeType<?>, RecipeType<GTChemicalReactionRecipe>> TYPE =
        TYPES.register(DIRECTORY,
                () -> RecipeType.simple(ResourceLocation.fromNamespaceAndPath(GoldenTweaks.MODID, DIRECTORY)));
```

序列化器可以复用基础版的（JSON 形状一样），但**类型必须独立**，否则两台机器会抢同一批配方。

### 2.4 客户端界面（可选，只有换贴图时才要）

```java
public class GTAdvancedChemicalReactorScreen extends GTChemicalReactorScreen {

    public GTAdvancedChemicalReactorScreen(GTChemicalReactorMenu menu, Inventory inventory, Component title) {
        super(menu, inventory, title);
    }

    @Override
    protected ResourceLocation texture() {
        return ResourceLocation.fromNamespaceAndPath(GoldenTweaks.MODID,
                "textures/gui/advanced_chemical_plant_gui.png");
    }
}
```

然后在 `GTChemicalReactorClientEvents.registerScreens` 里加一行：

```java
event.register(GTAdvancedChemicalReactorMultiblock.MENU.get(), GTAdvancedChemicalReactorScreen::new);
```

> 界面类共用 `GTChemicalReactorMenu`，所以 `createMenu` 返回的菜单类型必须正确——这正是 `menuType()` 钩子的作用。

### 2.5 挂到注册入口

`GTMultiblockBlocks.register()` 里加一行：

```java
GTAdvancedChemicalReactorMultiblock.register(eventBus);
```

**注意**：这段代码在 `if (ModList.get().isLoaded("avaritia_more_items"))` 分支里——多方块主机依赖 AMI，没有 AMI 不注册。

### 2.6 创造模式标签页

`GTMultiblockCreativeTabs` 里加一行（按 id 字符串找，因为主机由两条注册路径之一提供）：

```java
acceptExternal(output, "goldentweaks:advanced_chemical_plant_controller");
```

## 三、资源文件（8 类）

命名约定：方块 id `xxx_plant_controller`，结构文件名 `xxx_reactor`。

### 3.1 结构文件（两份！）

`data/goldentweaks/multiblock/structures/advanced_chemical_reactor.json`
`assets/goldentweaks/multiblock/structures/advanced_chemical_reactor.json`

```json
{
  "layers": [
    ["xxx", "xxx", "xxx"],
    ["xxx", "xox", "xax"],
    ["xxx", "xxx", "xxx"],
    ["xxo", "xxx", "oxx"]
  ],
  "keys": {
    "a": { "block": "goldentweaks:advanced_chemical_plant_controller" },
    "x": "#goldentweaks:multiblock/advanced_casing"
  },
  "master": "a",
  "any": "o"
}
```

**语义**：

- `layers`：从**底层**往上，每层从北往南，每行从西往东
- `a`：主机位置（`master`）
- `x`：机壳格，指向标签
- `o`：结构空位（`any`），可放任意方块、不计数、不校验

### 3.2 机壳标签

`data/goldentweaks/tags/block/multiblock/advanced_casing.json`

```json
{
  "replace": false,
  "values": [
    "#goldentweaks:multiblock/ports",
    "goldentweaks:shell_pp"
  ]
}
```

**必须包含 `#goldentweaks:multiblock/ports`**，否则仓室放不进结构。

### 3.3 方块状态

`assets/goldentweaks/blockstates/advanced_chemical_plant_controller.json`

384 个变体 = `facing(6) × mirrored(2) × running(2) × crafting(2) × roll(4) × formed(2)`。

三种状态位含义：

| 属性 | 含义 | 贴图 |
|---|---|---|
| `formed=false` | 未成型 | `_unconstructed` |
| `formed=true, running=false` | 已成型但关机 | `_off` |
| `formed=true, running=true, crafting=false` | 已成型、开机、空闲 | 基础态（idle） |
| `formed=true, crafting=true` | 正在跑配方 | `_working` |

用 `script/multiblock/` 下的脚本生成，别手写。

### 3.4 方块模型（32 个）

每个状态 × 每个 roll × 镜像/非镜像。

**四个状态各自的三层结构**：

| 状态 | 层数 | 第三层 |
|---|---|---|
| idle | 3 | `#name`（名称牌） |
| off | 2 | 无 |
| working | 3 | `#arrow`（箭头） |
| unconstructed | 2 | 无 |

**roll 旋转**：`_roll1/2/3` 要给 `overlay`、`name`、`arrow` 三个面写 `"rotation": 90/180/270`。漏了的话左键旋转主机纹丝不动。

**镜像**：
- `overlay` 的 UV 翻转为 `[16, 0, 0, 16]`
- `name` / `arrow` 换成 `_mirrored` 专用贴图（见下）

### 3.5 贴图

| 文件 | 说明 |
|---|---|
| `advanced_controller.png` | idle 正面 |
| `advanced_controller_off.png` | 关机 |
| `advanced_controller_working.png` | 运行中 |
| `advanced_controller_unconstructed.png` | 未成型 |
| `advanced_controller_name.png` | 名称牌 |
| `advanced_controller_arrow.png` | 箭头 |
| `advanced_controller_name_mirrored.png` | **镜像名称牌** |
| `advanced_controller_arrow_mirrored.png` | **镜像箭头** |

**镜像贴图的正确做法**：不是水平翻转内容，而是**整图右移 5 像素**，内容保持原样。

```python
img = Image.open("advanced_controller_name.png")
out = Image.new("RGBA", img.size, (0, 0, 0, 0))
out.paste(img, (5, 0))   # 只平移，不翻转
out.save("advanced_controller_name_mirrored.png")
```

这样镜像时文字方向正常、只是位置跟着翻转过去。

### 3.6 物品模型

`assets/goldentweaks/models/item/advanced_chemical_plant_controller.json`


指向 idle 模型（不带状态后缀的那个）。

### 3.8 工具标签 + 语言文件

### 3.9 配方目录

`data/goldentweaks/recipe/advanced_chemical_reaction/*.json`

目录名必须等于 `GTXxxRecipes.DIRECTORY`。**空目录机器不会报错，但什么都不会做。**

## 四、自检清单

新机器建好后逐条核对：

```
[ ] 结构文件两份齐全（data + assets），内容一致
[ ] 方块注册时传了结构文件名 + 实体工厂
[ ] MACHINE_ENTITY 的 id 与 MACHINE 相同
[ ] 实体六个钩子全部覆写
[ ] MENU 已注册，客户端 registerScreens 已加
[ ] 机壳标签包含 #goldentweaks:multiblock/ports
[ ] 32 个方块模型：roll 有 rotation，镜像有专用贴图
[ ] 镜像贴图是平移 5px，不是翻转
[ ] 物品模型指向 idle
[ ] 战利品表存在
[ ] pickaxe 标签 + 语言键
[ ] 创造标签页加了 acceptExternal
[ ] 配方目录与 DIRECTORY 同名
```

## 五、已经踩过的坑

| 现象 | 根因 |
|---|---|
| 放置方块直接崩溃 | 注册方块时没传实体工厂，或工厂与方块实体类型不匹配 |
| 界面一打开就关闭 | ① `menuType()` 没覆写 ② `stillValid()` 硬编码了基础版方块 id |
| 投影仪完全没反应 | ① `structureForHost` 只认基础版 ② 结构文件缺 `assets/` 那份 |
| 左键旋转无效果 | 模型缺 `"rotation"` 字段 |
| 镜像时名字位置不对 | 缺 `_name_mirrored` / `_arrow_mirrored` 贴图 |
| 拆除还回错误方块 | `createHostStack()` 硬编码了基础版物品 |
| 机器完全不工作 | 配方目录为空 |

## 六、以后的扩展方向

如果要加**同一台账下多种机壳**（例如某格可放聚乙烯或聚丙烯）：

- 结构文件的机壳标签里并列列出即可，`GTMultiblockBuilder.casingFor()` 会取第一个非港口成员
- 投影仪按**每格自己的符号**解析，不同符号可用不同标签，无需改代码

如果要加**不同形状**的机器：新建结构文件即可，不需要新增 Java 类——方块只需传自己的 `structurePath`。
