# 整合包帧率 / 低帧（1% low）问题排查报告

- 目标实例：`E:\机械动力魔法大冒险\.minecraft\versions\hkx`（NeoForge 1.21.1，555+ 模组）
- 排查日期：2026-09-28
- 依据：`options.txt` / 各渲染 mod 配置 / `logs\latest.log`（16:04 那次启动）/ 模组清单，结合此前 spark 与堆快照证据（见《内存问题排查报告.md》）

---

## 0. 结论摘要（先看这里）

硬件不弱（**RTX 4080 Laptop** + Iris/Sodium），问题不在 GPU 性能，而在**客户端被"多层装饰 + 多个功能重叠的优化 mod + 拦截渲染/光照的 mod + 82 个资源包"层层加重**，再叠加**内存接近上限导致的 GC 卡顿**。低帧（1% low）尤其来自：**实体/方块实体渲染、动态光照、纹理/模型图集过大、以及 Iris 与若干 mod 的渲染拦截冲突**。

**立刻可做且收益最大的 4 件事：**
1. 移除或禁用 **Vista（+vista_plus）**——它自己就在日志里承认与 Iris 同存会掉帧（与是否开着色器无关）。
2. 移除 **Tritium**——它在覆盖 Sodium 的渲染器 mixin，已经报冲突。
3. 退出 **RivaTuner Statistics Server (RTSS)**（或把它对 javaw 的注入关掉）。
4. 修 **帧率/垂直同步**组合（当前 `maxFps=130` + vsync + sodium-extra adaptive sync 三者叠加，典型"平均帧还行但 1% low 很差"）。

## 2. 高置信度成因（附证据）

### 2.1 Vista + Iris：**mod 自己承认会掉帧** ⚠ 最高优先
```
[Vista/]: IRIS mod detected. Vista WILL have visual issues and degraded performance.
This is not something that I can fix and happens even with shaderpacks off.
```
- Vista（`vista-5.5.2` + `vista_plus`）是内嵌 ffmpeg 的视频播放 mod。它与 Iris 共存即掉帧，**且与是否开着色器无关**。这是本次日志里最直白的一条"性能自诉"。

### 2.2 Sable + Flywheel：替换了光影/光照存储
```
[Sable/]: Sable is loaded with Flywheel. Sable contains extensive shader overrides and a
full light-storage replacement. Expect this to cause compatibility issues.
```
- Sable（Create 物理/子关卡）**替换了光照存储**，等于每个方块亮度都走它的路径。大面积移动/装置多时是实打实的掉帧源。

### 2.3 Tritium 与 Sodium 的 mixin 冲突
```
Method overwrite conflict for getNearest in sodium-common.mixins.json:...DirectionMixin
  from mod sodium, previously written by org.craftamethyst.tritium.mixin.client.renderer.immediate.DirectionMixin. Skipping method.
Method overwrite conflict for addVertex / setNormal ... previously written by tritium ... Skipping method.
Static binding violation: PRIVATE @Overwrite method setSectionDirty in sodium-common.mixins.json:core.render.world.LevelRendererMixin
```
- Tritium（26.10-hotfix）在改 Sodium 的**渲染器内部**（方向混合、顶点消费、区块脏标记）。冲突意味着优化**失效或行为不确定**，是低帧/偶发卡顿的常见来源。

### 2.4 RivaTuner Statistics Server (RTSS) 注入进程
```
[Sodium-Win32ModuleChecks/]: RivaTuner Statistics Server (RTSS) has injected into the process!
  Attempting to apply workarounds for compatibility... (RTSS 7.3.5)
```
- RTSS 的 OSD 钩子会干扰帧生成/帧率统计，Sodium 还要专门兼容它。**建议排除 javaw.exe**。

### 2.5 Revelationary + Sodium：区块重建走 "cursed mode"
```
[revelationary/]: Sodium/Rubidium detected. Chunk rebuilding will be done in cursed mode.
```
- 移动时区块重建会更慢 → 走动卡顿（hitching）。

### 2.6 EMF / ETF 调成了"最高细节" + FreshAnimations
- `entity_model_features.json`：`retainDetailOnLowFps = true`（**低帧时不减细节**）、`modelUpdateFrequency = "Average"`、`animationLODDistance = 20`、`resetPlayerModelEachRender = true`
- `entity_texture_features.json`：`textureUpdateFrequency_V2 = "Fast"`、`enableEmissiveTextures/EnableEnchantedTextures/enableBlinking/skinFeatures` 全开
- 资源包里有 **FreshAnimations v1.10.4**（+ Whimscape×FA、ThaumcraftTaintFix_FA）

→ 实体动画 + 皮肤/发光纹理是**每帧 CPU 开销**，怪物多/人多时 1% low 直接崩，是典型"掉帧点"。

### 2.7 Flywheel 灯光 = SMOOTH
`flywheel-client.toml: lightSmoothness = "SMOOTH"`，其自带注释即写 **"May have a large performance impact"**。Create 装置一多就是持续掉帧。

### 2.8 LambDynamicLights 全开 + fancy
`lambdynlights.toml: mode = "fancy"`, `entities = true`，且实体白名单极长（projectile/display/lightning 等全开）→ 每帧动态光源更新，压低 1% low。

### 2.9 资源包过载（82 个）
启用的包包含且不限于：
- **CTM/连接纹理**：`[机械]CTM Create`
- **PBR 材质**：`[主体]Create-LabPBR-v12`、`[主体]AE2-1.21-LabPBR-v9`
- **实体动画**：`[动画]FreshAnimations_v1.10.4`（+2 个 FA 配套包）
- **动画物品/3D 模型**：`animated-items`、`RAYs_3D_Ladders`、`3d-bamboo-shoots`
- **巨型音效包**：`[音效]Cataclysmic_tunes_V8 ≈ 86 MB`、`[音效]Enhanced Audio r7 ≈ 19 MB`
- 主体/汉化/界面/GUI 共几十个

后果：纹理图集与 VRAM 增大、首次加载/重载卡顿、每帧动画纹理更新成本上升、模型烘焙更久。日志还伴随 `continuity_reserved` 缺图、`Found 'parent' loop`、Mekanism 颜色标记缺失等一堆告警。

### 2.10 优化 mod 层叠 / 重复
同屏装了：`sodium(+extra)`、`lithium`、`krypton`、`ferritecore`、`modernfix`、`badoptimizations`、`chloride`、`flerovium`、`nolijium`、`tritium`、`entityculling`、`moreculling`、`cullleaves`、`optileaves`、`leavesbegone`、`immersive_optimization`、`dynamic_fps`、`smoothchunk`、`fastasyncworldsave`……
- `chloride / flerovium / nolijium / tritium` 都属于"与 Sodium 同层或相邻的渲染优化"，彼此以及和 Sodium 覆盖 mixin（见 §2.3）。**同类只该留一套。**
- `config\saturn-optimizations.toml` 仍在，但**未发现 saturn 的 jar**（残留配置，可清）。

### 2.11 内存压力 → GC 卡顿（与上一份报告联动）
- 实测堆常在 ~11.8 / 12.9 GB、一度触发 90% 告警。堆接近上限时，GC 会制造**周期性 frame spike**——表现为"平时还行，隔一会儿顿一下"。
- 详见《内存问题排查报告.md》：WorldEdit 静态方块表 ~1.84 GB、CIT Resewn ~332 MB、约 207 万 `ItemStack` 等。

### 2.12 UI / 菜单
- `menuBackgroundBlurriness = 5`：**每次打开背包/菜单都对世界做一次高斯模糊** → 开关界面时的顿挫。
- `ModernUI 3.13` + Mandala GUI 系列 6+ 个界面包 + `guiScale=4`（2560×1440 下 4 倍缩放的 UI 元素非常大，重绘面积大）。
- `drippyloadingscreen` + `fancymenu` 自定义加载界面。

### 2.13 帧率上限 / 垂直同步叠加
- `maxFps=130` + `enableVsync=true` + `use_adaptive_sync=true`：三者同时开容易产生**帧节奏抖动**。在 4080 + 视距 6 下游戏本可轻松超过 130，结果被 vsync 卡住，出现"帧数不低但感觉卡/1% low 很烂"。

### 2.14 其他值得注意
- `[tweakeroo/tweakerge]` 的视角摇晃 Redirect 与 Iris 冲突（`@Redirect conflict ... Skipping mixin`）——小问题但说明渲染拦截很多。
- 内容侧的重量级渲染：`RenderBlender`、`TRender`、`create_optical`、`sable`、`aeronautics`（物理）、`exposure`（摄影）、`chatimage`、`netmusic`、`spectrum`/`cataclysm`/`traveloptics`/`irons_spellbooks`（大量特效与自定义模型）、`yes_steve_model`/`touhou_little_maid`/`azurelib`/`geckolib`（实体模型库）。

## 3. 处置建议（按性价比）

### P0 — 立刻做（零风险，最可能见效）
1. **移除/禁用 Vista 与 vista_plus**（§2.1）。需要看视频时再临时启用。
2. **移除 Tritium**（§2.3）；如需 Create 渲染加速，优先信任 Flywheel/Sodium 自带。
3. **退出 RivaTuner Statistics Server**，或在 RTSS 里把 `javaw.exe` 加入排除（§2.4）。
4. **修帧率/同步**：二选一——
   - 只用 vsync：设 `maxFps` 略高于刷新率（如 165Hz 屏设 160）；
   - 只用 adaptive sync：`enableVsync=false`、`use_adaptive_sync=true`、`maxFps=显示器刷新率-3`。
   - 不要三者同时开（§2.13）。

### P1 — 画质换帧（收益明显）
5. `config\flywheel-client.toml`：`lightSmoothness = "FLAT"`（§2.7）。
6. `config\lambdynlights.toml`：`mode = "quality"` 或 `entities = false`（§2.8）。
7. EMF/ETF 降档（§2.6）：EMF 设 `retainDetailOnLowFps=false`、`modelUpdateFrequency="Low"`、`animationLODDistance` 调小；ETF 设 `textureUpdateFrequency_V2="Slow"`，按需关 emissive/enchanted/blinking/skin。
8. **精简资源包**（§2.9）：先关掉 CTM（Create CTM）、LabPBR（Create/AE2）、`animated-items`、3D 模型类、以及两个巨型音效包；保留主体/汉化/必要界面即可。这一项通常对 1% low 帮助很大。
9. `options.txt`：`menuBackgroundBlurriness=0`（§2.12）。
10. `config\continuity.json`：**若不再使用 CTM 资源包，整体关闭**（`connected_textures=false`、`emissive_textures=false`），否则两套 CTM/发光叠加很贵。

### P2 — 结构性
11. **优化 mod 去重**（§2.10）：`chloride / flerovium / nolijium / tritium` 与 `sodium` 同层，只留一套；删掉残留的 `saturn-optimizations.toml`。
12. **先解决内存**（§2.11）：见上一份报告——不用 WorldEdit 就移除（可省 ~1.8 GB）、不用 CIT 材质就移除 CIT Resewn、堆调到 16 GB。堆不紧张了，GC 卡顿会明显减少。
13. **Sable + Flywheel 的光照替换**（§2.2）：若 Create 物理/子关卡不是核心玩法，评估移除 Sable；否则留意其更新以便修复。
14. 若之后要开 **Complementary Unbound 着色器**：当前 82 个资源包 + 该光影会大幅掉帧，建议先按 §P1.8 精简资源包再开。
