一、先说结论
--------------------------------------------------------------------------------
1. ApotheosisDescHelper 本身不计算、也不显示“位阶/量子化/阿卡那”的数值。
   它只在按住 CTRL 时，给特定物品追加一行“x数量 书架名”的静态提示，
   告诉你用哪些书架可以凑出该灌注配方所需的属性。

2. 按 Apothic Enchanting 1.6.2/1.6.4 + Apotheosis 8.9.0 的真实数据逐条计算：
   - 16 个提示物品、20 条提示布局中，18 条能正确满足配方；
   - 2 条错误，且都是“量子化超过配方上限”，会导致灌注失败：
       * 药水护符（potion_charm）
       * 末影书架（ender_library）

3. 还有两个它完全没有提到、但会直接影响“三维属性”的前提：
   - 附魔台自带 +15 量子化（以及 +1 线索）；
   - 位阶受玩家“最大位阶”属性限制，而该属性由世界层级决定：
       居所 30 / 边境 45 / 攀升 60 / 高峰 75 / 顶点 100。
     所以很多提示只有在对应世界层级才能成立，低层级照抄会失败。

4. 结论：它可以在“书架数量”层面间接提供三维属性搭配，但不能直接给出三维数值，
   并且有 2 条提示是错的、也没有提示世界层级限制。作为参考可用，不能盲信。

二、Apothic Enchanting 的三维属性与计算规则
--------------------------------------------------------------------------------
官方中文名（apothic_enchanting/lang/zh_cn.json）：
  Eterna  = 位阶
  Quanta  = 量子化
  Arcana  = 阿卡那

附魔台基础值：
  位阶   0
  量子化 +15（EnchantmentTableStats.Builder 构造函数）
  线索   +1

每个书架/方块提供：
  位阶、量子化、阿卡那，以及“位阶上限(maxEterna)”。

位阶计算（EnchantmentTableStats.Builder.build）：
  1) 先按每个方块的 maxEterna 分组，把同组的位阶相加；
  2) 按 maxEterna 从小到大处理：
       maxEterna > 0：位阶 = min(maxEterna, 当前位阶 + 该组位阶之和)
       maxEterna = 0：位阶 = 当前位阶 + 该组位阶之和
  3) 最终把位阶限制在 [0, 100]；
  4) 实际生效位阶 = min(台面位阶, 玩家“最大位阶”属性)。
     玩家“最大位阶” = 100 + 当前世界层级修正
     （居所 -70、边境 -55、攀升 -40、高峰 -25、顶点 0）。

量子化 / 阿卡那：
  台面值 = 15 + 所有方块量子化之和（阿卡那没有基础值）
  然后限制在 [0, 100]。

灌注配方判定（InfusionRecipe.matches）：
  位阶 >= requirements.eterna
  量子化 >= requirements.quanta
  阿卡那 >= requirements.arcana
  并且，如果 max_requirements 的某项不是 -1：
    该项必须 <= max_requirements，超过即失败（大于才失败，等于可以通过）。
  注意：位阶用的是“实际生效位阶”（受世界层级限制），量子化/阿卡那用台面值。

--------------------------------------------------------------------------------
六、世界层级（MAX_ETERNA）对三维属性的影响
--------------------------------------------------------------------------------
Apothic Enchanting 的“最大位阶”属性基础值是 100（范围 0~100）。
Apotheosis 的世界层级会以 add_value 方式叠加修正
（data/apotheosis/tier_augments/*/max_eterna.json）：

  世界层级        修正      实际最大位阶
  居所 haven      -70       30
  边境 frontier   -55       45
  攀升 ascent     -40       60
  高峰 summit     -25       75
  顶点 pinnacle     0       100

实际生效位阶 = min(台面位阶, 实际最大位阶)。
因此下面这些提示只有在足够高的世界层级才能成功（否则位阶被截断）：

  最低可在“居所(30)”成立的：蜂蜜瓶 1→1（位阶 20）
  最低可在“边境(45)”成立的：三叉戟/惰性三叉戟（40）、高级刷取宝典（45）、
                              末影拴绳两方案（45）
  最低可在“攀升(60)”成立的：紫水晶块/紫水晶芽（60）、提取宝典（60）、
                              深暗书架方案A/B（60）、蜂蜜瓶 1→8（60）
  最低可在“高峰(75)”成立的：回响碎片（70）、神秘末影拴绳（75）
  最低需要“顶点(100)”的：  药水护符（100）、末影书架（100）、
                              附魔台满属性布局（100）、
                              龙息/注魔之息（80，高峰75不够）、
                              蜂蜜瓶 1→32（100）

DescHelper 完全没有提示这一点；它列出的书架数量假设玩家已经能拿到足够高的
位阶上限。在低层级照抄高层级配方，会显示“配方不符合灌注需求/灌注失败”，
不是书架摆错了。请以游戏内 CTRL+T 显示的当前世界层级为准。

七、其他问题与使用限制
--------------------------------------------------------------------------------
1. 不显示数值：它只显示“x数量 书架名”，不会显示最终位阶/量子化/阿卡那，
   也不显示是否满足配方。要自己按第二节的规则计算。
2. 客户端 + CTRL：只在客户端、按住 CTRL 时显示；不按 CTRL 只显示一行
   “[灌注附魔助手]：按住 CTRL 查看”。
3. 版本敏感：书架属性和灌注配方都是数据驱动的。以后 Apothic Enchanting /
   Apotheosis 改数值或换版本，这些静态提示就会失效。本次已核对 1.6.2/1.6.4
   的 enchanting_stats 完全一致；但上述两条错误依然存在。
4. 覆盖不全：至少以下灌注配方没有提示：
   - 胡萝卜 → 金胡萝卜
   - 音乐唱片（Eterna / Quanta / Arcana 三张）
   - 下界书架 → 注魔下界书架
   - 海洋书架 → 注魔海洋书架
   - 宝石箱 → 末影宝石箱（Apotheosis）
5. 输入/输出提示错位：
   - 深暗书架：配方输入是“休眠深暗书架(dormant_deepshelf)”，但提示只加在产物
     “深暗书架(deepshelf)”上；拿着输入物品看不到提示。
   - 末影书架：输入是“魔导图书馆(library)”，提示只加在产物上。
   - 末影拴绳：输入是“脆弱末影拴绳(flimsy_ender_lead)”，提示只加在产物上。
   - 高级刷取宝典：输入是“刷取宝典(scrap_tome)”，提示加在产物上。
   - 神秘末影拴绳：输入是“拴着女巫的末影拴绳”，但所有末影拴绳都会显示普通
     末影拴绳配方（9 澄澈海洋 / 9 耀光+8 蜡烛），不会显示神秘配方的 75/85/60。
6. 附魔台“最佳布局”加在“原版附魔台(minecraft:enchanting_table)”上，
   而不是“神化附魔台(apothic_enchanting:apothic_enchanting_table)”物品上；
   后者物品栏里看不到这条提示。
7. 蜡烛提示按“8 个蜡烛物品”计算阿卡那 +10；如果摆成多蜡烛方块，总数仍按
   蜡烛支数 ×1.25 计算，结果一致。
8. 中文：mod 自带 en_us/ru_ru；本工作区的
   src/main/resources/assets/apotheosisdeschelper/lang/zh_cn.json 提供了 9 个
   中文键（分隔线、或、最佳附魔搭配、CTRL 提示等），书架名来自
   Apothic Enchanting 的 zh_cn。
9. 它不处理“过滤书架/宝藏书架/稳定”等特殊效果；只列数量，不解释效果。

九、核对依据（可复现）
--------------------------------------------------------------------------------
- DescHelper 反编译：org/blackhole/descriptions/DescriptionEvent.addTooltips()
  - 只在 Screen.hasControlDown() 时追加；
  - 所有“xN 书架”都是硬编码；
  - 不包含任何位阶/量子化/阿卡那计算。
- Apothic Enchanting：
  - table/EnchantmentTableStats.java：+15 量子化、+1 线索、
    按 maxEterna 分组封顶、[0,100] 限制；
  - table/EnchantingStatRegistry.java：JSON 优先，否则回退
    getEnchantPowerBonus()*2；
  - table/infusion/InfusionRecipe.java：min 与 max_requirements 的严格判定；
  - objects/GeodeShelfBlock.java：位阶 10 / 量子化 -15 / 上限 60 / 提供稳定；
  - objects/TreasureShelfBlock.java：位阶 10 / 量子化 -15 / 阿卡那 -15 /
    上限 70 / 允许宝藏；
  - mixin/CandleBlockMixin.java：阿卡那 +1.25 × 蜡烛数；
  - data/apothic_enchanting/enchanting_stats/*.json：其余书架数值；
  - data/apothic_enchanting/recipe/infusion/*.json：灌注配方；
  - Ench.java：MAX_ETERNA 基础值 100。
- Apotheosis：
  - data/apotheosis/recipe/infusion/potion_charm.json：
    requirements 100 / 8.5 / 32.5，max 100 / 13.5 / 37.5；
  - data/apotheosis/tier_augments/*/max_eterna.json：世界层级位阶修正；
  - compat/enchanting/CharmInfusionRecipe.java：药水护符灌注沿用
    InfusionRecipe.matches。
- 1.6.2 与 1.6.4 的 data/apothic_enchanting/enchanting_stats/*.json 逐文件
  比对一致；GeodeShelfBlock/TreasureShelfBlock 的常量也一致（均为 -15 量子化）。
